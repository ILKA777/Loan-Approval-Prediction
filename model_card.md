# Loan Approval Prediction — Model Card

## 1. Model Information — сведения о модели

### Описание

Loan Approval Prediction — учебная модель бинарной классификации
табличных данных кредитных заявок.

Модель предсказывает score положительного класса `loan_status=1`
на основании характеристик заявителя, кредита и кредитной истории.

Бизнес-смысл значений целевой метки должен быть подтверждён
документацией источника данных. До такой проверки score не трактуется
как вероятность одобрения кредита или вероятность дефолта.

### Архитектура

Модель реализована как единый `scikit-learn Pipeline`,
содержащий preprocessing и классификатор.

Числовые признаки обрабатываются следующим образом:

1. `SimpleImputer(strategy="median")` заполняет пропуски медианой.
2. `StandardScaler` стандартизирует значения.

Категориальные признаки обрабатываются следующим образом:

1. `SimpleImputer(strategy="most_frequent")` заполняет пропуски
   наиболее частым значением.
2. `OneHotEncoder(handle_unknown="ignore")` кодирует категории.

`ColumnTransformer` объединяет результаты преобразований.
Затем `LogisticRegression` рассчитывает score положительного класса.

Параметры классификатора:

```python
LogisticRegression(
    class_weight="balanced",
    max_iter=1000,
    random_state=42,
)
```

Preprocessing обучается только на обучающей части данных.
На validation и при предсказании применяются уже обученные
преобразования.

### Входные данные

Модель использует 11 признаков.

| Признак | Тип | Описание |
|---|---|---|
| person_age | Числовой | Возраст заявителя |
| person_income | Числовой | Доход заявителя |
| person_emp_length | Числовой | Стаж занятости |
| loan_amnt | Числовой | Сумма кредита |
| loan_int_rate | Числовой | Процентная ставка |
| loan_percent_income | Числовой | Отношение суммы кредита к доходу |
| cb_person_cred_hist_length | Числовой | Продолжительность кредитной истории |
| person_home_ownership | Категориальный | Форма владения жильём |
| loan_intent | Категориальный | Цель кредита |
| loan_grade | Категориальный | Категория кредита |
| cb_person_default_on_file | Категориальный | Признак наличия дефолта в истории |

Описания соответствуют названиям колонок. Точные единицы измерения,
правила формирования полей и их бизнес-смысл требуют проверки
по документации исходного датасета.

`id` — идентификатор строки. Он используется для связывания
предсказаний с исходными данными и не входит в признаки модели.

### Выходные данные

Выход модели — score положительного класса, полученный через:

```python
model.predict_proba(features)[:, 1]
```

При пакетном предсказании формируется `reports/submission.csv`:

| Колонка | Содержание |
|---|---|
| id | Идентификатор строки из test.csv |
| loan_status | Score класса 1 в диапазоне от 0 до 1 |

Калибровка не проверялась. В частности, использование
`class_weight="balanced"` не позволяет автоматически считать
score подтверждённой вероятностью события в реальной популяции.

Порог преобразования score в бизнес-решение не определён.

## 2. Model Data — данные модели

### Данные обучения

Исходный файл `train.csv` содержит:

- 58 645 строк;
- 13 столбцов;
- 11 входных признаков;
- идентификатор `id`;
- целевую метку `loan_status`.

Распределение целевой метки:

| Класс | Количество строк | Доля |
|---|---:|---:|
| 0 | 50 295 | Около 85.8% |
| 1 | 8 350 | Около 14.2% |

В данных присутствует дисбаланс классов.
Для обучения используется `class_weight="balanced"`.

### Данные для предсказания

Файл `test.csv` содержит:

- 39 098 строк;
- 12 столбцов;
- идентификатор `id` и 11 входных признаков;
- не содержит целевой метки.

Файл `sample_submission.csv` задаёт ожидаемые имена
выходных колонок: `id` и `loan_status`.

### Происхождение данных

В рамках подготовки этой карточки не подтверждены:

- первичный источник и способ сбора;
- реальный или синтетический характер данных;
- период наблюдений;
- географическое покрытие;
- состав популяции;
- лицензия и допустимые способы использования;
- точный бизнес-смысл целевой метки.

Наличие CSV в репозитории само по себе не подтверждает
репрезентативность, качество или право на использование данных.

### Подготовка данных

До обучения:

1. Целевая колонка отделяется от входных данных.
2. Выбирается фиксированный набор из 11 признаков.
3. `id` исключается из признаков.
4. Данные делятся на обучение и validation.
5. Preprocessing обучается на обучающей части.

Отсутствие необходимой колонки приводит к ошибке.
Пропуски обрабатываются внутри preprocessing pipeline.

Полная проверка диапазонов значений, дубликатов,
связанных заявителей и корректности бизнес-правил
пока не реализована.

не зафиксированы.

## 5. Evaluation — оценка качества

### Методика

Оценка выполнена на отложенной части `train.csv`.

Параметры разбиения:

```python
train_test_split(
    features,
    target,
    test_size=0.2,
    random_state=42,
    stratify=target,
)
```

Размеры выборок:

| Выборка | Количество строк |
|---|---:|
| Обучающая | 46 916 |
| Валидационная | 11 729 |

Стратификация сохраняет соотношение классов.

Preprocessing и классификатор обучаются только
на обучающей части.

### Результаты

Подтверждённый результат запуска 4 октября 2026 года:

| Метрика | Значение |
|---|---:|
| Validation ROC-AUC | 0.90681 |

ROC-AUC рассчитывается по score положительного класса.
Она характеризует качество ранжирования и не является
долей правильных классификаций.

### Область применимости результата

Результат относится к одному фиксированному случайному
разбиению имеющегося датасета.

Он не подтверждает:

- качество на реальных новых заявках;
- качество в другой популяции;
- устойчивость при изменении условий кредитования;
- корректность калибровки;
- справедливость для отдельных групп;
- положительный бизнес-эффект.

В текущей реализации сохраняется модель, обученная
на 80% `train.csv`. Повторное обучение на всей размеченной
выборке после оценки не выполняется.

`test.csv` не используется для измерения качества,
поскольку целевые метки для него недоступны.

### Неизмеренные показатели

Пока не оценивались:

- Average Precision и PR-AUC;
- precision, recall и F1;
- confusion matrix при выбранном пороге;
- калибровка и Brier score;
- доверительный интервал ROC-AUC;
- качество на других разбиениях;
- внешняя и временная валидация;
- качество по отдельным группам;
- стоимость ошибок и бизнес-эффект.

## 6. Intended Usage and Limitations — применение и ограничения

### Назначение

Модель предназначена для учебной демонстрации:

- бинарной классификации табличных данных;
- воспроизводимого обучения;
- пакетного предсказания;
- оценки baseline-модели;
- организации ML-кода и автоматических проверок.

### Пользователи

- разработчик проекта;
- преподаватель и проверяющие;
- аналитики, изучающие pipeline и baseline.

### Использование вне области назначения

Без дополнительной проверки модель не должна использоваться:

- для автономного одобрения или отказа в кредите;
- для принятия решений о реальных клиентах;
- как проверенная оценка вероятности дефолта;
- для другой страны, продукта или популяции;
- для решений, требующих подтверждённой fairness
  и правовой оценки.

### Известные ограничения

1. LogisticRegression может не учитывать сложные
   нелинейные зависимости и взаимодействия признаков.

2. Оценка выполнена на одном случайном разбиении.

3. Происхождение и репрезентативность данных
   не подтверждены.

4. Семантика целевой метки требует уточнения.

5. Калибровка и качество по группам не проверены.

6. Не реализованы мониторинг и автоматическое переобучение.

7. Обработка неизвестных категорий предотвращает
   часть технических ошибок, но не гарантирует
   сохранения качества.

8. Не проверена доступность всех признаков
   в момент реального решения. Например, `loan_grade`
   и `loan_int_rate` могут зависеть от этапа процесса.

9. Не проверены повторные заявители и связанные
   наблюдения между train и validation.

### Рекомендации перед реальным применением

- Подтвердить источник, условия использования данных
  и смысл меток.
- Проверить отсутствие утечки данных.
- Выполнить внешнюю или временную валидацию.
- Измерить дополнительные метрики и калибровку.
- Оценить качество по релевантным группам.
- Выбрать порог с учётом стоимости ошибок.
- Предусмотреть человеческий контроль.
- Реализовать мониторинг изменения данных и качества.

## 7. Ethics and Safety — этика и безопасность

### Риски смещения

Исторические метки могут отражать прежние решения
и существующие смещения.

Возраст, доход, занятость и форма владения жильём
могут быть связаны с социальными характеристиками
заявителей. Качество и последствия использования
модели могут различаться между группами.

Отдельный fairness-аудит не проведён.

### Приватность

Кредитные заявки могут содержать чувствительную
персональную и финансовую информацию.

Перед использованием реальных данных необходимы:

- проверка законности обработки;
- минимизация собираемой информации;
- ограничение доступа;
- обезличивание, где применимо;
- безопасное хранение и передача.

Исключение `id` из признаков само по себе
не обеспечивает анонимность данных.

### Безопасность артефактов

Артефакты `joblib` следует загружать только
из доверенных источников.

Модель и результаты предсказания исключены из Git.
Секреты и локальные переменные окружения
не должны попадать в репозиторий.

### Человеческий контроль

При возможной бизнес-интеграции модель должна
рассматриваться как компонент поддержки решения.

Текущий проект не реализует автоматическое кредитное
решение, механизм апелляции или объяснение решения клиенту.

### Выполненные и невыполненные проверки

В проекте настроены:

- разделение обучения и validation;
- единый preprocessing pipeline;
- фиксированный random_state;
- проверки кода и unit-тесты;
- управление зависимостями через Poetry;
- исключение локальных артефактов из Git.

Эти меры не заменяют:

- fairness-аудит;
- проверку калибровки;
- оценку приватности;
- юридическую проверку;
- внешнюю валидацию качества.
